## Findings

### Critical (block ship) — fixed

1. **REST POST 404s before WS connects** — writing a thread via
   `POST /api/docs/:id/threads` returned `{"error":"doc not found"}` if the
   widget hadn't opened a WebSocket first. Even though the widget always opens
   WS first in practice, REST can race ahead; more importantly any external
   script or curl hitting REST without WS would fail.
   **Fix:** `packages/server/src/server.ts` now auto-creates the room on
   any write path under `/api/docs/:id/…`. GETs still 404 for unknown
   docs (that semantic is preserved).

### Issues (should fix before ship) — fixed

2. **Picker mode has no visible affordance for "cancel"** — when the user
   clicks "Comment on element…", the only way to exit picker mode is Esc or
   clicking an element. A user who entered the mode by mistake has no
   visible way out and might panic-click.
   **Fix:** `packages/widget/src/widget.ts` now shows a top-center banner
   reading "Click any element to leave a comment." with an inline
   **Cancel (Esc)** button for the duration of picker mode. Bundle cost:
   +0.1 KB gzipped (still 33.9 KB).

### Polish (post-ship OK) — not addressed tonight

3. **Landing page has no "create doc" flow** — users must POST `/api/docs`
   from curl or the MCP server. A simple form would help, but the expected
   workflow is agents create docs; humans open links. Deferred.

4. **Markdown app's Cmd+M shortcut is undocumented** — the welcome seed
   mentions the Comment button but not the keyboard shortcut. A tooltip on
   the toolbar would help. Deferred.

5. **`?as=bryan` vs `?as=agent` links in the mockup footer** — the demo
   surfaces them in tiny footer text. Most users will not find them. For a
   demo this is fine; for production the widget's panel could expose
   "Switch user" explicitly. Deferred.

6. **No connection-state indicator in the markdown app toolbar** — the
   widget has one (in its panel header). The markdown app does not. A
   "connecting / online / offline" chip would match the widget. Deferred.

7. **Mobile responsiveness not verified** — CSS has breakpoints at 1100px
   and 800px but I could not walk a real mobile viewport.

### What worked well

- Widget Shadow DOM isolation looks correct on read: no selectors leak into
  the host page; the only light-DOM footprints are the overlay/pin layer
  (marked with `data-feedback-widget`) and a single scoped `<style>` block
  (`#cfw-light-styles`) for pin hover states.
- Custom element API is idempotent: `FeedbackWidget.init()` called twice
  returns the same element (covered by a vitest).
- Text-range anchors survive concurrent edits (covered by a Yjs convergence
  test that pokes two docs).
- The element fingerprint scoring (ported from health-tool) has the same 40
  threshold and survives id removal when other attrs remain (covered by a
  happy-dom test).

## What I could NOT verify offline

- Live typing in CodeMirror with two open clients converging.
- Mermaid rendering of the seed code-fence (require a real browser).
- Selection → floating Comment button appearing.
- Widget pin repositioning on scroll / HMR.
- Cross-origin WS from Vite (:5173) to feedback server (:8787).
- Keyboard-only flow through composer and thread panel.
- Mobile layout at 375px.
