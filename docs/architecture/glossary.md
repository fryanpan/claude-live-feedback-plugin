## Decisions for Bryan

1. **hub vs board** — the directory said `hub`, the UI says "board", and the URL says `/workspaces/:id`. 
  1. Decided (Bryan, 2026-09-02: "Board is good"): the screen is the Board; rename the hub/ directory and hub-* modules to board in the rename pass; the URL keeps /workspaces/:id because the workspace is the container.
  2. **Shipped 2026-09-05** — see rename order step 5.
2. **The four senses of "review"** — review item (a person's queue), review set (a folder or diff bind), review doc (a bound markdown file), and the document editor route `/review/<docId>`. 
  1. Decided (Bryan, 2026-09-02): "review" means only the person-facing queue (review item).
  2. Everything a board holds for people to comment on — doc, mockup, preview (dev server), diff — is an "Attachment"; 
  3. a review set becomes an attachment set, and URL paths follow the Google API design guide (plural collection names, `/collection/{id}` nesting): 
  4. The /review/<docId> editor route becomes /workspaces/{id}/docs/{docId}, matching the existing /workspaces/{id} and /api/tasks. Decided (Bryan, 2026-09-02).
    1. All attachments are owned by a workspace so ownership and permissions are clearSo the URL structure should reflect that going forward
  5. **Names shipped 2026-09-05; the routes are half-shipped** — the board's own routes and two name collisions cleared 2026-09-05, the doc/task/attachment-set collections are still open — see rename order step 6.
3. `packages/markdown-app`
  1. Rename to `workspaces-app` (the whole browser client: editor, Home and board, sign-in, landing), rename to `editor`, or leave it and accept that the code surface and diff surface live inside a package named for markdown?
  2. Bryan: Rename to `workspaces-app` 
  3. **Shipped 2026-09-03** (PR #629) — the directory and package name moved ahead of the rest of this lane; this decision's own "shipped" note went missing until this pass. The `@feedback/*` npm scope did not move with it (see the code-names table).
4. **`DocHome`** — the type means a doc's repo of origin, which reads as the Home page. 
  1. Rename to DocOriginRepo (Bryan, 2026-09-02); the Home page keeps its name.
  2. **Shipped 2026-09-05** — see rename order step 6.1.
5. **redline vs suggest** — two distinct product concepts, not one. Suggestion is the proposal made in Suggesting mode (Accept / Reject). Redline is the change view: struck deletions, marked insertions and margin balloons, used to show suggestions and, through the same diff algebra in core/src/redline.ts, git diffs in a diff review. Decided (Bryan, 2026-09-02): keep both names; the only rename is moving the suggestion UI files (suggestion-chips, suggestions-summary) out of the redline/ folder into suggestions/. **Shipped 2026-09-05** — see rename order step 6.1.
6. **Huddle** — the UI mostly said "Have a discussion" and "Make a plan" and only called the artifact a Huddle. 
  1. Decided (Bryan, 2026-09-02): drop "Huddle" from the UI; the two kinds are Plan and Meeting notes, and the button becomes "Have a meeting". Code may keep huddle as the shared container until the rename pass.
  2. **Shipped 2026-09-02, words only.** No user-visible string says Huddle any more. The identifiers listed in the concept table above were deliberately left alone so the rename lane can move them in one pass rather than in a copy-edit.
7. **`park_task`** — the `parked` task state was removed in August 2026 and the verb now means "move to triage and leave a note" (`server/src/park-note.ts`, `park-migration.ts`). 
  1. Decided (Bryan, 2026-09-02): triage is confusing as a parking place; add a Blocked state meaning "waiting on a dependency or a date", park_task becomes block_task and moves a row there with the reason. Filed as its own task.

## Suggested rename order

Renames run **after** the current file-split lanes land, so nothing here competes with a lane's diff.

1. **Done 2026-09-04.** The CSS class prefix, the `data-` attribute prefix, the browser storage keys and the test scratch-dir prefixes all read `cw-`, and the legacy env aliases are gone. The single exception is `HUB_FEEDBACK_DOC_ID`, whose value names a live doc in the corpus. Ticket: "CSS and env prefix" ticket.
2. **Done 2026-09-04.** The MCP verbs read `attach_mockup`, `attach_folder`, `spin_off_task` and `archive_workspace`; each keeps the name it had as an alias for one release, which says so once per session in the MCP log. Ticket: "MCP verbs" ticket.
3. park_task → block_task and a Blocked task state that replaces Triage (Decision 7, decided: blocked means waiting on a dependency or a date). One MCP verb and two server modules whose name outlived the state they described. Tickets: "Blocked state" ticket, then "MCP verbs" ticket.
4. **Done 2026-09-05.** `rooms.ts` is `doc-store.ts` and `Rooms` is `DocStore`, along with `RoomsConfig`, `rooms-workspaces.ts`, `room-timings.ts`, `makeRooms`, `isHubOwnedRoom` and every `rooms` local across the server and its suites. Purely internal: no REST path, MCP tool name or response field moved. Ticket: "DocStore" ticket.
5. **Done 2026-09-05.** hub/ → board/ and Hub* → Board* (Decision 1, decided): `markdown-app/src/hub/` is `workspaces-app/src/board/`, `HubNav`/`HubPane` are `BoardNav`/`BoardPane`, and every `hub-` CSS class and `hub.css` moved to `board-`/`board.css`. Touched roughly thirty modules and the CSS. Ticket: "board/" ticket.
6. review → attachment (Decision 2, decided). Split in two: the names half has landed in full, and the routes half has landed in part.
  1. **Names done 2026-09-05.** A review set is an ATTACHMENT SET in the code and in every user-visible string: `core/src/review.ts` is `attachment.ts` with `reviewIdOf` → `attachmentIdOf` and `isReviewMember` → `isAttachmentMember`, `server/src/review-backfill.ts` is `attachment-backfill.ts`, "Back to all review docs" is "Back to all attachments", the landing fold reads "Attachments by project", and the doc-list sidebar and its CSS banner say attachment set. `DocHome` is `DocOriginRepo` in `doc-origin-repo.ts` (Decision 4), and `suggestion-chips.ts` and `suggestions-summary.ts` left `redline/` for `suggestions/` (Decision 5) — covered by `workspaces-app/test/suggestions-outside-redline.test.ts`, which renders both on the plain markdown surface with no redline module loaded. "Review" now means only a person's queue of review items. Nothing moved on the wire: `setId`, the `reviewId` bind field, the `docHome` meta key, the `reviewUrl` listing field and every URL path stayed put. Ticket: "attachments" ticket.
  2. **The board's own routes are canonical (2026-09-05); the resource collections are not yet.** Three things landed together, and they are the half of the cutover whose callers already carry a workspace id. **The `/api` prefix is gone from the board family:** every `/api/workspaces/{id}/…` route now answers at `/workspaces/{id}/…`, which is the same address as the board's own page — HTML by default, the record with `?format=json`. One list of what is a page (`routes/workspace-path.ts`) is read by the thing that serves them and by the thing that must not claim them, so the two cannot drift. **`/api/goals/{goalId}/…` is now `/workspaces/{id}/goals/{goalId}/…`:** a band no longer names a row and leaves the server to find its board. **And one middleware resolves the board** (`middleware/workspace-scope.ts`), above every handler: it answers whether the board exists and whether the row named under it belongs to that board, refusing both with the same 404, and the per-route existence checks it replaces were deleted. Membership stays where it already lived, in `shareScopeAllows`. No old-path support: the previous addresses were deleted in the same change that moved every in-repo caller, and the `/api/reviews` alias arm that answered a review under `/api/workspaces/{setId}/…` went with them. The share allowlist was re-derived for the merged prefix — a board's pages and a board's data are one table now, and a goal verb asks two questions (the segment is the shared board AND the row is inside it). **Still open:** the resource collections and their REST subroutes — docs, tasks and attachment sets, dozens of routes under `/api/docs`, `/api/tasks` and `/api/reviews` between them. **The document editor's page address moved already, as a narrower case:** `/workspaces/{id}/docs/{docId}` is what `shell-static.ts` links to and serves, and `/review/{docId}` now redirects there when a workspace resolves (compat, not slated for removal) — but that is the HTML shell only; the JSON record and its ~30 subroutes (threads, edit ops, plan, meeting-bot…) are still addressed at `/api/docs/{docId}/…`, and `/api/reviews` (the attachment-set collection) hasn't moved at all. **The prerequisite that blocks the rest is unchanged and is a decision, not work:** no MCP tool that addresses a doc, task or attachment set carries a workspace id — `get_doc(docId)`, `task_transition(taskId)`, `archive_attachment_set(reviewId)` and ~40 others take the resource id alone — so with no old-path support those tools cannot spell a canonical path at all. Either the tool surface gains the id (a fleet-wide change to every skill and habit) or the MCP resolves it client-side, which is the same lookup the move exists to delete. The two name collisions were cleared first and separately, on the same day: the attached-agent roster left /workspaces/{id}/attachments for **/workspaces/{id}/agents**, freeing `attachments` for the noun this glossary spends it on, and the board's live feed left /events/workspace/{id} for **/workspaces/{id}/events:stream**, leaving `events` to the activity feed it collided with. Two grouped with this lane already shipped on their own schedule: markdown-app → workspaces-app landed 2026-09-03 (PR #629), ahead of the routes work rather than alongside it, and the Huddle strings → Plan / Meeting notes with a "Have a meeting" button (Decision 6) shipped 2026-09-02. Still open in this lane: the @feedback/* scope → @claude-workspaces/* (Decision 3). Tickets: "canonical routes" ticket, "workspaces-app" ticket, "Plans and Meeting notes" ticket.
